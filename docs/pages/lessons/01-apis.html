What is an API?

An Application Programming Interface (API) is a structured way to request data from a service. For researchers, an API is “programmable search + download”:

  • Predictable formats: usually JSON, sometimes XML or CSV
  • Documented inputs: the parameters you can filter on
  • Standardized outputs: the same fields every time

Every example in this lesson follows the same data journey:

API Request ──► JSON / XML Response ──► Parse & Flatten in R
            ──► Data Frame (Tibble) ──► (Optional) Save as CSV

The researcher loop

  1. Identify source + documentation: read the API docs before writing any code
  2. Draft a query: fields, filters, and time range
  3. Request data: respect rate limits
  4. Validate + clean: check dimensions, types, and missing values
  5. Save raw + processed data
  6. Record provenance: URL, parameters, date, and API version

Ground rules

  • Prefer official APIs and bulk downloads over scraping
  • Respect terms of use, rate limits, and institutional policy
  • Avoid collecting PII/PHI
  • Use caching and delays to reduce load on the server
  • Document provenance: what you requested, when, and from where
